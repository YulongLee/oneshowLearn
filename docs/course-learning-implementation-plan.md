## 实施结论

采用增量升级：保留现有课程、章节、资料库、账号、订单与权益，扩展现有课程阅读器，不另建一套课程平台。

本次新增的核心是：**课时编排、视频/PPT 同步、时间点富文本笔记、学习状态持久化、课程 AI 服务接口，以及贯穿所有资源的付费访问控制。**

设计图决定布局与交互层级，不作为真实课程、用户、进度、会员权益或 AI 回答的数据来源。公共首页、工作台、实战项目、独立 AI 导师、社区的视觉设计不在本次重做范围内。

需要先批准本文，再按阶段编码。本轮不迁移数据库、不上传课程、不部署生产。

## A. 当前项目分析

| 项目 | 核查结果 | 本次处理 |

| 前端 | React 19、Vite 6、JavaScript/JSX | 保留，不整体迁移框架或 TypeScript |

| 登录 | JWT、bcrypt、邮箱验证、账号状态与 token version 校验 | 复用现有会话和角色；不增加第二套登录 |
| UI | 共用 `WorkspaceShell`、顶栏、可调侧栏、Phosphor 图标及白紫色样式 | 复用品牌、账号、搜索和响应式约定 |
| 内容 | CMS 管理课程包、章节、八种内容格式、发布、排序、资料引用与附件 | 增加课时编排界面，不在前端硬编码真实课程 |

| AI | 现有导师为明确标注的界面示例；未发现可复用的真实模型服务 | 新建服务抽象，未配置时诚实显示不可用 |
| 支付 | 已有商品、订单、支付记录、权益；只有人工确认收款 | 复用账务模型，真实支付渠道另行接入 |

### 2. 现有数据并非空白项目

- `project_packs` 已承担课程实体；`project_steps` 承担章节。
- `content_items` 是章节中的资料投放记录；`content_library` 是可复用的资料源。不能复制成互不关联的另一套内容。
- `progress` 记录资料级“已开始/已完成”，尚无视频位置、PPT 页和课时播放会话。
- `workspace_state` 保存个人任务、笔记、收藏和打卡，采用版本校验。它适合现有轻量个人记录，不适合把全部富文本时间线笔记每秒整体覆盖保存。
- `practice_projects` 是独立实战项目，可关联课程；目前没有完整的“项目阶段—课时练习”关系。
- `entitlements` 已保存用户、课程、来源和有效期，不需要再建重复的 `UserCourseAccess` 主表。

### 3. 现有阅读器与目标差距

`CourseReader.jsx` 当前以单份资料阅读为主，能够读取 CMS 内容、判断访问权和记录完成状态；尚不具备完整课时聚合、PPT 查看、同步映射、时间点笔记和真实 AI。

特别需要修复的已有基础问题：

1. 视频识别目前依赖资源 URL 后缀；私有附件地址形如 `/api/materials/:id?ticket=…`，没有 `.mp4` 后缀。应改用服务端返回的媒体类型，而非猜测 URL。
2. 私有资源票据有效期有限，长视频需要续期与断点恢复；播放、字幕、缩略图、课件文本均须鉴权。
3. 现有“开始学习”写入可能覆盖完成状态，新播放心跳必须保证完成状态不会因并发退回未完成。
4. 课程价格为 0，目前不自动等于免费；新访问类型必须显式配置，不能迁移时意外开放付费资料。
5. 现有人工收款确认使用的管理角色范围较宽。涉及收款、退款的权限应与内容编辑权限分离。

### 4. 本轮验证结果

- 已在本地浏览器检查现有课程阅读流程；本地服务可用。
- `npm test`：83 项通过，其中前端模型/平台测试 37 项、API 测试 42 项、Sites 测试 4 项。
- `npm run build`：通过，并生成 Sites 所需构建产物。
- 存在大于 500 kB 的 JavaScript 包体积警告；新增编辑器、PDF 查看器等应按需加载。
- 当前没有 TypeScript 配置和 Lint 脚本，不能把“构建通过”描述为已经通过 TypeScript/Lint 检查。

上述仅为**现有系统基线**，不是新课程系统的验收结果。已有未提交改动将保留，不做全仓重置或无关重构。

## C. 需要新增的模块

### 1. 课时编排与后台维护

采用 `课程 → 章节 → 课时 → 关联资料`。新增的课时不是新课程，而是把现有视频、PPT、图文、代码、附件、练习组合成一次学习单元。

管理员可配置课时标题、副标题、排序、发布状态、试看、必学内容、主视频、课件、字幕/文字稿、资料和实践任务。PPT 与视频时间映射在后台维护，并可在发布前预览。草稿不暴露给学员；删除采用归档，编辑保留版本冲突检查。

不按截图自动生成课程，不按标题猜测 OPC 阶段，不擅自把所有旧资料一键变成“新课时”。

### 2. 专注学习布局

建议在同一个 `WorkspaceShell` 内增加学习模式：保留全局顶栏，左侧导航槽替换为课程目录，避免“工作台侧栏 + 课程目录 + 主内容 + 笔记”挤成四栏。退出学习后恢复用户原来的侧栏宽度、折叠和隐藏偏好。

- 宽桌面：约 260px 目录 + 自适应主内容 + 约 340px 笔记。
- 可用宽度不足：先将目录折叠为抽屉，再把辅助笔记切换为面板；不压缩阅读字号强塞三栏。
- 手机：视频、内容/PPT 纵向排列；目录抽屉；笔记底部面板，保留附近的保存/状态提示。
- 顶部显示课程/章节/课时面包屑、标题、副标题、上一节/下一节。
- 左侧目录支持当前、完成、锁定、试看和真实时长；下载 Tab 使用同一鉴权资料清单。
- 当前章节优先展开，状态不能仅靠颜色区分；控件至少 44px，抽屉支持键盘和焦点返回。

这一课程专注模式属于**待确认的实现建议**，不改变其他学习页面的公共侧栏。

### 3. 视频播放与恢复

基于原生 HTMLMediaElement 包装播放器，提供播放、拖动、时长、音量、倍速、全屏和真实字幕轨道。没有字幕/多清晰度源时，不展示虚假的字幕或“高清切换”功能。

保存播放位置、媒体版本、当前课件页、最后学习时间及完成状态。约每 10–15 秒保存一次，暂停和切课时补存；关闭页面仅做尽力保存，不能承诺浏览器强制关闭时绝不丢失最后一秒。

恢复需等待媒体元数据加载，位置限制在实际时长内。显式深链接时间点优先于历史播放位置，不自动有声播放。

### 4. PPT 查看与视频同步

浏览器不直接可靠渲染任意 PPTX。首个可用版本支持：

- 上传原始 PPTX 作为受保护下载附件。
- 同时上传导出的 PDF 或有序页面图片，作为在线课件；后台查看页数、缩略图和顺序。
- PDF 使用按需加载的 PDF.js；图片按当前页附近懒加载。字幕与页面文字支持后台提供，用于搜索/AI。
- PPTX 自动转 PDF/图片放入独立转换任务，只有部署了受限转换工作进程、字体和资源限制后才启用；转换失败必须可重试并保留原件。

课件支持缩略图、分页、放大/全屏、下载原件和笔记标注。每页具有稳定 ID 和课件版本，避免换课件后旧笔记悄悄指向错误页面。

同步模式：

1. 默认跟随视频；按 `[startTime, endTime)` 区间定位 PPT 页。
2. 用户手动翻页后进入自由浏览，展示“恢复跟随视频”。
3. 恢复跟随后立即定位到当前时间对应页。
4. 点击时间点笔记时跳转视频并显示笔记绑定页，进入自由浏览，避免立刻被时间映射覆盖。
5. 未配置映射或时间区间没有命中时不猜测页码；提供清晰状态。

后台校验区间重叠、负数、越界、无效页和媒体版本变化；替换视频后提示重新核对映射。

### 5. 富文本笔记与截图

提供加粗、斜体、下划线、列表、链接、图片；候选采用 Tiptap 的基础开源扩展，安装前确认依赖、许可和包体积，不依赖付费托管服务。

- 编辑区 700–1000ms 防抖自动保存，中文输入法组合输入结束后保存。
- 展示“保存中 / 已保存 / 保存失败 / 发生冲突”，切课或离开时处理未保存内容。
- 时间线笔记绑定 `lessonId + videoTime + slideId`，支持编辑、删除到回收站和恢复。
- 数据逐条版本控制；快速切课、多个标签页或离线恢复不能让旧响应覆盖新内容。
- 私有图片和截图有本人权限、文件校验及配额；富文本输出需消毒，不执行任意 HTML。
- 截图从允许读取的当前视频帧或课件页面产生，支持简单框线、箭头、文字标注并保存。跨域视频被浏览器禁止截图时明确提示，不能用假成功替代。

课程笔记同时出现在“学习笔记”页面，按来源/课程筛选。旧 Markdown 笔记保留原数据，不能因新编辑器上线而丢失。

### 6. 课程 AI

新增服务器端 `courseAIService`，提供能力查询、总结、知识点、整理笔记、思维导图、复习卡片、课程问答接口。模型密钥只保存在服务端配置。

上下文由服务端按当前用户权限组装：课程、章节、课时、授权字幕/文字稿、授权 PPT 文字、用户选定的本人笔记。返回引用到课时、时间点或页面；内容不足时说明不足，不编造课程事实。

首版 RAG-ready：定义检索接口及来源结构，先做按课时/页面检索，不为了架构名词强制引入向量数据库。后续可替换为向量检索，仍保留逐资源权限过滤。

未配置真实模型时返回明确的未配置状态，保留本地笔记功能，不生成伪 AI 回答。AI 结果经用户确认后另存笔记，不覆盖原文。限制请求长度、频率、并发、超时与费用；发送私人笔记前告知范围。

### 7. 实践与商业化闭环

实践任务复用现有 task/checklist 内容，增加稳定的清单项、当前用户提交状态，以及明确的实战项目阶段关系。不把个人日常任务当作课程作业，也不因勾选清单颁发证书或宣称产品已上线。

购买沿用已有商品、订单和权益：试看 → 查看价格/权益 → 创建订单 → 支付渠道 → 服务端验证通知 → 生效权益 → 学习。尚未选择支付服务商时，只展示真实可用的购买/人工确认途径，不能把创建订单当作支付成功。

### 新增实体

| 实体 | 核心字段与用途 |

| `course_lessons` | 章节、标题、副标题、状态、排序、试看、版本；形成学习单元 |

| `lesson_progress` | 用户+课时唯一；播放位置、时长、课件页、跟随状态、完成时间、最后学习时间、版本/会话序号 |
| `course_notes` | 用户、课时、富文本 JSON、纯文本索引、时间点、稳定页 ID、附件引用、版本、归档状态 |

支付接入阶段如需支持同一课程的购买、赠送、会员等多种权益并存，增加授权流水 `entitlement_grants`，现有 `entitlements` 作为有效权限投影；退款只撤销对应来源，不误伤其他有效授权。真实退款另建关联原订单/支付的退款记录，不覆盖原支付事实。

### 进度、笔记与迁移口径

- `CourseProgress` 使用聚合查询/服务返回，不额外维护一份容易失步的课程百分比。
- 新课时课程按已完成的已发布课时计算；旧课程继续按原资料计算，返回 `progressUnit` 明确“课时/资料”。工作台、课程库、OPC 使用同一聚合服务。
- 旧 `progress` 原样保留。管理员确认课时与资料关联后，可依据真实必学资料完成记录预览迁移结果；未完成或没有记录的内容不能推测完成。
- `course_notes` 存储新增课时笔记；现有 `workspace_state` 笔记不复制一份。统一笔记读取层聚合两类来源，修改时按来源写回，旧的整体状态保存不能清空新增课时笔记。
- 权益的购买时间从关联订单 `paid_at` 等真实来源读取；人工赠送使用授权时间，不伪装购买日期。
- 迁移先在隔离数据库执行，检查外键、旧 ID/正文/进度/权益/笔记保留和重复执行安全性。未收到部署请求不得在生产执行。

### 统一接口约束

1. 所有课时资源逐层检查课程/章节/课时/资料发布状态、关联关系、用户状态和有效权益，不能只保护目录。
2. 预览课时不自动开放其引用的全部付费附件；必须明确配置可试看资料。后台发布前检查访问规则冲突。
3. URL 中课时/课程/资料必须匹配；不能改 ID 读取其他课程、其他用户笔记或草稿。
4. 更新采用版本号/`If-Match`；过期编辑返回 409，不能静默覆盖。完成状态不被后到的播放心跳降级。
5. 未登录、无权益、未发布/不存在、冲突、超限、AI 未配置分别给出可处理的状态；不把错误变成成功空数据。
6. 原始文件、视频 Range 请求、字幕、PPT 页面文字/缩略图、下载和 AI 检索都执行一致的访问检查。
7. 内容编辑者与财务确认操作分权。回调不能由浏览器直接调用“支付成功”替代。

### 分阶段交付边界

- Phase 1–7 可先建立完整的真实课程学习闭环，无需先购买 AI 服务或支付套餐。

## I. 风险与需要确认的事项

### 关键风险

1. **历史内容兼容**：目前是资料级学习，新课时编排不能重置学习记录或改掉已经购买的课程范围。用显式关联、迁移预览和兼容阅读器控制风险。
2. **付费内容泄漏**：不能只锁视频；字幕、PPT 图/文、缩略图、原件、AI 引用也可能泄漏。所有派生资源继承访问约束。旧公开资源若需要变为私有，需管理员重新上传/替换。
3. **媒体能力**：50 MB 上限和单机文件存储不一定适合正式视频课程。批准后测量真实文件大小、并发与带宽，再决定对象存储/CDN或分片上传；不擅自采购或迁移。
4. **PPT 还原度**：动画、字体、特殊图表不保证静态 PDF 能完整表达。明确首版以静态课件为准，原始 PPTX 可下载；自动转换需要隔离任务和失败恢复。
5. **自动保存竞争**：后台响应乱序、多标签页和切课会造成覆盖。逐条版本控制、请求取消、冲突提示及用户隔离的待保存草稿防护优先于“始终显示已保存”。
6. **完成标准**：拖到视频末尾不等于真的掌握课程。首版支持用户明确完成，并记录可核查播放状态；不把它包装成考试合格、实名认证证书或防作弊能力。
7. **AI 的可信与成本**：无上下文时不编造；课程材料中的文本不作为服务端指令执行；不能让检索越过其他课程/用户权限。外部模型隐私、保留策略及预算需要明确。
8. **支付闭环**：人工确认不是线上收银台。渠道签名、重复通知、异常退款和多来源权益都要验证，不能只做一个“购买成功”弹窗。
9. **性能与数据库**：SQLite 可继续使用，但视频心跳与笔记写入必须节流；按实际并发做压测后再讨论数据库拆分，不在本次凭空重构。
10. **安全边界**：富文本/上传文件需校验与消毒；外部素材导入不可任意抓取内网 URL。下载权限与短期票据不是 DRM，无法承诺防录屏或彻底防复制。

### 本轮建议确认

建议批准：**单一课程数据源 + 显式课时编排 + 共用 shell 的专注学习模式 + 保留旧资料/笔记/进度**。

后续接入时再提供的配置，不需要阻塞 Phase 1：

- 第一门真实课程的视频、原 PPTX、导出 PDF/页面图片与字幕/文字稿。
- AI 服务商、模型、服务端密钥配置方式和预算；不要把密钥写进前端或文档。
- 支付渠道、商户资质与测试配置；尚未决定时保留人工确认能力。
- 是否启用会员商品及其真实权益规则；未确定时不承诺无限 AI 或全部课程权益。
- 是否部署独立 PPTX 转换服务，以及视频存储/带宽方案。
