# 用户端商业化布局检查

检查日期：2026-09-27

后续状态：本报告指出的核心学习入口、工作台层级、手机阶段折叠、笔记触控和公开搜索问题已在同日修复并部署；自测与发布证据见 `commercial-layout-release-20260927.md`。以下保留原检查结果，内容配置及未开放服务仍需后续完成。

## 结论

新版用户端已具备统一视觉和基本响应式基础，可以继续内测；尚不建议按“商业化布局及交付验收完成”处理。最优先的问题不是换配色，而是仍可进入旧学习界面、任务层级不合理、移动端仅堆叠内容，以及部分承诺尚无真实内容支撑。

本次仅检查，没有修改产品代码、线上配置或用户资料，没有部署。

## 范围与方法

- 主路由：工作台、AI OPC、学习路线、实战项目、AI 导师、资源中心、社区、笔记、收藏、成果、课程、学习计划、会员、账号。
- 14 个主路由分别检查 390、768、1366、1440、1920、2560px，共 84 组视口布局测量；关键页面补充截图和交互检查。
- 补充公开首页、登录、注册、找回密码、学习路线详情、项目包详情以及旧学习页；沿“项目包详情 → 进入项目学习”检查真实导航。
- 主要在本地同版本前端检查：生产首页文件与本地构建首页 SHA-256 一致；生产公开内容接口只读核对。生产浏览器会话部分访问超时，因此不把本地测试说成全部线上端到端验收。
- 当前测试账户的笔记、收藏、成果等主要为空状态；没有为了测试往线上写入示例数据。

## 已具备的基础

- 新版主页面侧边栏、搜索栏、激活态和紫白配色基本统一。
- 主路由上述测量中没有发现整页横向溢出；宽屏容器、网格及中小屏侧栏降级规则已存在。
- 手机导航抽屉可打开；资源阅读弹窗在 390px 下能正常展示和关闭。
- 新版个人数据有诚实的空状态；AI 导师演示、社区筹备状态有说明。

“没有横向溢出”不等于“移动布局已经好用”，也不代表所有数据量和异常状态均已验收。

## 优先问题

### P1：真实学习链路仍进入旧版界面

复现：`/packs/cursor-first-site` 点击“进入项目学习”进入 `/learn/cursor`。

- 旧页面没有新版共享工作空间导航，用户会感到切换到了另一套产品。
- 进度按固定 `35 + completed * 5` 显示，步骤状态包含硬编码，不是完整的当前账户学习记录。
- 资源按钮仅显示“已打开”的提示，没有实际打开对应资源；导师回答也是固定逻辑。
- 项目包详情的学习按钮只放行 `cursor-first-site`，其他已拥有项目包在该入口显示“阅读功能完善中”。这不代表所有其他阅读入口不可用，但该详情链路不完整。

位置：`src/App.jsx` 的 `ProductPackPage`、`LearningWorkspace` 和 `/learn/cursor` 路由分支（约 151、172–195、258 行）。

建议：统一接入现有 CMS 内容阅读器及真实账户进度，保留同一导航和返回路径；删除固定进度和仅弹提示的假交互。收费发布前必须解决。

### P2：工作台优先级偏展示，而非日常学习

1440px 视口下，主横幅约 300px 高；继续学习区域约在页面纵坐标 493px，任务与日历所在侧栏约在 1379px，落在其他内容之后。

建议：首屏优先展示继续学习、今日任务和下一步。中等宽度下将任务提到学习进度附近，不要仅把整条侧栏移到页面最底部；已开始学习的用户可看到更精简的欢迎横幅。

相关：`src/workbench.css`、`src/workspace-responsive.css`。

### P2：移动端内容堆叠过长

390px 下学习路线页面实测高度约 4769px，五个阶段完整展开，再叠加推荐顺序、推荐项目和辅助区域。工作台及 AI OPC 页面也超过 3000px。

建议：当前阶段默认展开，其他阶段收起；保留阶段进度和下一步入口。任务、日历、导师建议按重要性排序，非必要推荐区折叠，而不是缩小字号来容纳所有内容。

### P2：字体与操作目标仍不统一

- 笔记编辑器部分工具按钮约 21 × 21px，手机端同样偏小。
- 笔记统计等辅助文字仍有 10px，部分其他模块有 9–11px 的细小文字。
- 手机新建笔记时保存按钮位于编辑区下方，需要较长滚动。

建议：建立正文、辅助文案和标题的统一字体层级；正文以 14–16px 为设计起点，辅助文案尽量不低于 12px；手机工具按钮可点击区域以 40–44px 为设计目标。长编辑区提供固定或就近保存反馈。这是设计建议，不是正式无障碍认证结论。

相关：`src/personal-workspace.css` 约 79、96 行；`src/ai-tutor.css`。

### P2：公开入口有含义与行为不一致

- 公开首页“学习社区”实际前往 `/resources`。
- 公开首页“搜索课程”输入框没有搜索提交或结果处理。

建议：导航名称与目标一致；搜索接入真实结果，或在未完成时取消搜索框，避免呈现可用功能的假象。

相关：`src/PublicHomepage.jsx` 约 25、28 行。

### 交付就绪问题：与布局问题分开管理

检查时生产公开实战项目列表为 0 个；AI OPC 课程接口的五阶段 `items` 均为空。AI 导师及社区仍为演示/筹备状态。

这些不应简单判定为前端布局故障，但会影响用户进入后的价值感知。需要在后台完成真实内容发布和课程映射；无内容时减少大面积空推荐区，对未上线功能降低视觉权重，明确开放状态。不要用虚构课程数、项目数或学员数据填充界面。

## 分页面建议

| 页面 | 检查结论与建议 |
| --- | --- |
| 工作台 `/app` | 主框架统一；继续学习与今日任务优先，减少展示横幅和空推荐区。 |
| AI OPC `/opc` | 保留阶段和章节主线；移动端收起非当前阶段，先补齐已发布章节映射。 |
| 学习路线 `/paths` | 桌面结构清晰；手机过长，改成当前阶段展开的路线结构。 |
| 实战项目 `/projects` | 目录布局成立；目前生产无已发布项目，空状态应更精简并明确后续路径。 |
| AI 导师 `/tutor` | 会话应占主要空间；学习上下文和建议在窄屏折叠，保持演示标识。 |
| 资源中心 `/resources` | 阅读弹窗可用；减少搜索、分类、标签的重复；分类网格避免宽屏出现不均衡尾行。 |
| 学习社区 `/community` | 尚在筹备；避免让大面积示例内容看起来像真实活跃社区。 |
| 学习笔记 `/notes` | 优先修复工具栏触控尺寸和保存位置；统计、推荐区降级。 |
| 我的收藏 `/favorites` | 主壳一致，空状态可用；后续需以长标题、大量内容验证筛选和网格。 |
| 我的成果 `/achievements` | 主壳一致；突出创建及展示成果，证书和统计必须来自真实数据。 |
| 我的课程 `/courses` | 浏览布局可用；必须修复详情到旧学习页的交付断点。 |
| 学习计划 `/plan` | 基础自适应通过；仍需用真实多任务数据补充密度和长文本测试。 |
| 会员 `/membership` | 视觉可用不代表交易验收通过；权益、购买状态须与实际开放能力一致。 |
| 账号 `/account` | 独立账号安全页面，未使用新版工作空间壳；建议明确“账号安全”名称与返回入口。 |
| 公开首页及认证页 | 补充尺寸检查未见整页横向溢出；修复社区链接及无功能搜索。 |
| 旧学习页 `/learn/cursor` | 当前商业化体验的首要问题：替换旧框架和固定状态，接入真实内容交付。 |

## 建议实施顺序与验收边界

1. 修复所有可达的学习入口与旧阅读页，统一导航、内容、进度和资源操作。
2. 整理工作台及各页面的信息优先级，优化平板和手机阶段展开方式。
3. 统一字号、间距、按钮触控区域、空状态和保存反馈。
4. 由管理员发布真实课程和项目，核对每个前台入口对应内容。
5. 使用普通学员及有真实学习数据的账户，补测长标题、长笔记、大量收藏、锁定内容、失败/断网状态；再进行真实设备和不同浏览器复验。

本次不包含支付、邮件送达、负载、安全、正式无障碍认证，也没有完成所有个人数据满载状态或 Safari/Firefox 真机测试。因此结论限定为布局和可见入口的商业化体验检查，不能替代完整上线验收。
