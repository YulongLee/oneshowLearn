# 支付宝电脑网站支付对齐（本地开发）

用户提供的可调用产品页面显示 OneShowLearn 应用已开通电脑网站支付；原实现调用当面付 `alipay.trade.precreate`，线上验签后的返回码为 `ACQ.ACCESS_FORBIDDEN`。这次只开发与自测，不部署、不改生产价格/密钥/开关，不创建真实支付交易。

## 新订单与历史订单

- 新支付宝订单使用 `payment_flow=page`。本地订单创建只准备付款，不向平台预创建交易，不返回伪二维码、不声称下单已被支付宝接受。
- 点击「前往支付宝收银台」后，由认证且拥有该订单的用户请求 `/commerce/orders/:id/pay`。服务端使用历史配置快照、原订单金额、卖家 UID、课程标题及受控回调生成官方 SDK `alipay.trade.page.pay` / `FAST_INSTANT_TRADE_PAY` 签名链接，客户端只允许 `https://openapi.alipay.com/gateway.do`。
- 此签名链接仅在上述操作的私有响应中返回；不存入日志/订单列表/管理诊断。SDK 在服务器签名，私钥永不下发。
- 使用原订单的绝对 `time_expire`，北京时间表示，重复进入不延长付款有效期。生成并返回过链接即记作 issued；这不是平台验签成功事件。
- 增量字段默认历史订单为 `qr`，保存老配置、金额、付款码、回调以及查单/关闭路径。新微信订单继续 Native 二维码。
- 未发出过链接的 page 订单可以本地关闭/切换；已发出链接但暂未查到交易的订单在绝对到期并经过 5 分钟安全窗口后，才可依据已验签的查无此单结果关闭。实际存在的未付交易仍须查单→关闭→复查；到账优先结算，不另建订单。

## 回跳、到账与权限

- `return_url` 只指向同站 `/membership?paymentReturn=<id>`。登录后仅恢复本人订单并查询；浏览器携带 `trade_status` 等不被当作付款证据。
- 权限只在验签回调或核验查询完成后开通，仍校验配置版本、订单号、应用/商户、精确金额及支付流水，幂等结算。
- 禁用/变更支付宝商户配置后不再为旧订单发链接；历史真实到账仍用原配置验签结算。
- 管理台明确「电脑网站支付」与基础连接测试的区别。连接通过、本地签名成功和模拟网关自测都不是生产收款验收。

## 自测

`npm run test:payment-page`：新 page 流程、本地真实 RSA2 签名、账户/输入/重放/回跳/到期限制、未使用与已发出链接切换、伪造回调、配置轮换与历史记录保留。传统支付套件使用隔离的历史 QR 传输选择器继续回归旧合同，不改变生产默认 page 流程。全站测试包含两个合同。

UI 预览使用独立 fixture 数据库与模拟网关；不在浏览器访问正式支付宝签名链接。真实支付宝官方收银台接受参数、展示方式与最终到账须由所有者部署后另行验收。

本地验收记录：全站 335 项测试通过，正式构建通过（保留已有大包体积提示）。浏览器验收确认支付宝准备订单展示官方收银台入口、未发链接订单切换至微信模拟二维码、微信经关闭复查切回支付宝，旧订单保留在历史列表。带 `trade_status=TRADE_SUCCESS` 的返回地址只恢复待支付订单，不开通权限。截图见 `artifacts/payment-page-pay/checkout-local.jpg`；画面价格为独立测试数据，不是生产价格变更。

官方接口参考：[支付宝 Node SDK pageExecute](https://github.com/alipay/alipay-sdk-nodejs-all)、[电脑网站支付接口](https://opendocs.alipay.com/apis/api_1/alipay.trade.page.pay)。
