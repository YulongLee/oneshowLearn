# 课程支付与后台定价 · 2026-10-01

## 本次范围

- `/membership` 展示站主指定售价 **¥399 / 原价 ¥799 / 优惠 ¥400**，延续既有销售页样式，不添加倒计时、销量、评价、退款承诺。
- `/admin/payments` 仅管理员可访问：选择售卖课程商品、修改价格、配置商户参数、加密保存私钥、独立开启微信/支付宝。编辑与发布课程仍使用现有 CMS。
- 微信直连商户 Native v3 扫码；支付宝当面付 precreate（官方 Node SDK v4 的 v3 接口）。不包含 H5/JSAPI 同设备拉起、订阅、自动退款。
- 服务器定价下单 → 本地生成二维码 → 支付平台签名通知/主动查单 → 核验商户、订单、金额 → 原子更新订单与课程权限。前端不能自行设置已支付。
- 待付款订单持久化，关闭弹窗不取消，重新打开可从“我的支付订单”恢复。创建失败继续使用相同订单号，避免重复下单。更换渠道前需要确认关闭旧订单。
- 没有商户信息时渠道禁用，不显示假二维码、不模拟支付成功。不会自动把演示课程设为真实收费商品。

## 后台配置清单

1. 在“课程与路径”创建实际售卖的课程商品并发布；在“支付与定价”明确绑定它。保存只同步该商品/课程价格，已有订单保留成交时金额。
2. 部署时运维单独生成 `PAYMENT_CONFIG_ENCRYPTION_KEY`（32 个随机字节的 64 位十六进制），设在服务器私有环境中，和数据库分开安全备份。不要提交 Git、不要传给浏览器。遗失主密钥会导致历史商户配置无法解密；不能随意替换。开发环境使用隔离数据库旁的 0600 本地密钥文件。
3. 微信：开通 Native 的直连商户号、绑定 AppID、商户 API 证书序列号、匹配的商户私钥 PEM、32 字节 APIv3 密钥、微信支付公钥 PEM 及 `PUB_KEY_ID_…`。不是公众号 AppSecret，也不是个人收款码。本版要求公钥模式，旧平台证书通知不接收，切换期可主动查单。
4. 支付宝：开通当面付的应用 AppID、卖家 UID/seller_id、应用私钥 PEM、支付宝公钥 PEM（不是应用公钥）。采用 RSA2 公钥模式，不是证书模式。
5. 回调根域名默认 `https://oneshowlearn.com`；每次配置保存生成不可变版本，下单自动携带 `/api/payments/notify/{provider}/{version}`。域名要能公网 HTTPS 访问，并将 `/api/` 反向代理到 API 服务；回调不能要求登录、验证码或跳转。保持服务器时钟同步。
6. 主密钥、私钥不回显；空输入保留旧值。配置有版本冲突保护，历史版本保留供未结清订单验证。切换商户/密钥之前需先结清原账户待付订单，旧商户侧密钥不能提前撤销。
7. 本版仅将二维码支付落实到绑定的单一课程，不授予其他独立课程、项目或订阅。

## 安全与验收

- WeChat 请求 RSA-SHA256 签名，明确发送公钥 ID；响应与回调按原始字节验签，回调 AES-GCM 解密，校验 AppID/mchid/CNY/分金额。拒绝签名探测、错误公钥 ID、超过 5 分钟的签名时间。
- Alipay 成功响应由官方 SDK 验签；通知用 `checkNotifySignV2`，避免表单重复解码，核验 app_id/seller_id/订单/金额。查单结果由签名请求与响应绑定应用，若包含 seller_id 也必须一致。
- 通知幂等；同一渠道流水不可用于两个订单。在线订单禁止后台人工“确认收款”；历史线下订单保留独立人工核验入口。
- 支付平台超时、验签失败、配置缺失或主密钥不匹配均不开放权限。创建未成功且到期的订单，只有收到平台明确“查无订单”结果才允许关闭，网络错误不能替代该结果。
- 新增 `tests/payments.test.mjs` 使用独立临时数据库、临时 RSA 密钥和模拟传输；测试真实签名、AES 解密及平台回调处理。未调用真实商户、未扣款。
- 最终完整回归通过：平台 93 项、API 106 项、Sites 4 项，合计 203 项。支付文件包含 12 个场景子测试（含官方 Alipay SDK 对实际签名字节的校验，网络被禁止）。构建成功（已有主包体积提示，不阻断构建）。
- 浏览器确认销售页价格、渠道未配置禁用、收银台和后台字段可读；320/390/768/1440/1920/2560 像素无水平溢出，390 像素收银台可正常关闭。后台在隔离本地数据库保存未启用渠道的默认价格配置后，重载仍为 399/799；没有把演示课程设为收费商品。
- 依赖审计：新增 Alipay SDK 传递依赖 urllib 的跨域重定向凭据泄露告警（GHSA-hq3h-g68c-hp78）通过限定 4.9.1 修复。仓库原有 browserslist、multer、nanoid、nodemailer、postcss、vite 等仍有安全告警，未在支付任务中执行全仓库强制升级；这些风险需在正式开放收款前单独升级与回归。功能测试通过不等于依赖安全审计清零。
- 更新 urllib 后构建与全部 203 项回归再次通过；最终在线审计因 npm 官方审计接口超时未完成，不能声明安全审计通过。首次有效审计报告为 9 项（含已修复的 urllib），其余既有依赖告警需后续处理。

- 退款需按商户正式售后流程人工处理，并同步核对平台订单与权益；本版不自动调用退款接口，不承诺退款周期。
